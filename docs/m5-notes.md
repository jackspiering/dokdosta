## Decisions the plan leaves open

1. **Events had no store.** The plan said the events table's ID "doubles as the `since` cursor" (§3.10), but M2 to M4 never built it: the bus counter lived in memory and restarted at 1. M5 adds the table (schema 3), seeds the bus from it, and makes retention apply to it (v3.9 item 1). `AUTOINCREMENT` (not plain `INTEGER PRIMARY KEY`, which can reuse the ID of a deleted newest row) keeps `sqlite_sequence` as the high-water mark, so retention cannot make an ID come back. A cap of 100,000 rows bounds a flapping container.
2. **A cursor ahead of the host is a reset**, not an empty page: a hub holding cursor 500 for a host whose store was wiped would otherwise wait forever. The reply carries `reset: true` and starts over; the SSE stream sends a `reset` event. A dry run restarts at 1 every time, so it resets by design.
3. **Token: bearer and Basic.** The brief said bearer. A browser cannot set `Authorization` on a navigation or an `EventSource`, and a login form would need a POST (refused by the read-only rule) and a cookie. HTTP Basic with the token as the password is native to browsers, needs no write endpoint and no state. The token is still never taken from the URL. **Approved** (follow-up 1), with the rule that both forms are for TLS only.
4. **`/healthz` stays open** on the TCP listener, as since M1, even with a token. It says only ok or not ok (follow-up 2). A reverse proxy or an uptime monitor can use it.
5. **`/metrics` behind `WHALENURSE_METRICS`** (default off), not always on: "optional" read as opt-in, consistent with the dashboard being off by default. Cardinality: two per-container families (`suspended`, `flaps`) for the watched containers only.
6. **Containers page lists the watched containers** (opted in, or a sidecar of an opted-in parent: what the last classification did not skip), with `?all=1` for the rest. The API does the same (`?all=1`). Counts on the overview say how many are not watched. Unwatched containers are shown with their labels filtered like the others.
7. **The drift status is the guard's last verdict** (from the event log), not a live check (v3.9 item 8). If the container was never recreated, the page says "nothing recorded". A live "would a recreate be blocked now" would need a compose dry-run per page view.
8. **Daemon read side.** The loop's index is single-goroutine, so the API reads a separate `view` (the last container list, and per key the last inspect and the rules' decision), written by the loop and read under an `RWMutex`. The page is therefore as fresh as the last poll (60 s) or event-driven look; the state column comes from the list (fresher), the restart count, exit code and start error from the last inspect of the same container ID.
9. **Server-side rendering** instead of the page fetching `/api/v1` from JavaScript: it works without JavaScript, has no inline data, and the CSP stays strict. "Uses only this API" is kept by structure (`internal/web` imports `internal/api` only; a test checks), not by HTTP loopback.
10. **Cut `State.Error`, show it.** It is the reason a container is down and is already in the event messages. It can name a host path (a bind source). Cut at 600 runes and redacted.
11. **Event attribute allow-list** (v3.9 item 6b) is a list of the 34 keys the engine and the daemon emit today, written by reading every `map[string]string{...}` and `attrs[...]` in `internal/engine` and `internal/daemon`. A new attribute has to be added to `allowedAttrs` to reach the API. The values of allowed keys are redacted but not otherwise inspected (the secrets test therefore plants its attribute secret under a key that is not allowed).
12. **Event streams do not hold events.** The hub only wakes clients; each client reads the log from its cursor, so the engine's lock is never held for I/O and a stalled browser tab costs nothing. At most 32 streams. In a dry run the log is a 5,000-event ring: a client that was slower than 5,000 events misses some (the stored mode has no such loss).
13. **Basic-auth challenge.** A 401 sends two `WWW-Authenticate` lines (Bearer, Basic) so that both a script and a browser know what to do.
14. **The API reads through its own SQLite connection.** The store's writer is a single connection and `RecordEvent` and `SaveKey` run under the engine's lock, so a page view on that connection could make the healing loop wait. `Query`, `LastID` and `History` use a second read-only connection (`mode=ro`, `query_only`; WAL lets it run beside the writer, and a test holds a write transaction open to prove a read does not wait). If it cannot be opened the reads share the writer's connection and a warning says so.
15. **HTTP server settings**: header timeout 5 s, read timeout 15 s, idle 2 min, no write timeout (the stream). Shutdown is graceful for 3 s (`RegisterOnShutdown(hub.Close)` ends the streams), then closed.

## Review follow-ups (the maintainer's answers, 19 Oct 2026; plan v3.9 items 11 to 16)

1. **Basic next to bearer: approved.** Password = the token, user name ignored, the same constant-time compare. Documented as TLS only (a proxy that terminates TLS, or Tailscale Serve), or loopback; the startup text and `docs/running.md` say so.
2. **`/healthz` open with a token, and only ok or not ok.** `PublicHealthHandler` writes `ok` or `not ok` (503). The old detail handler stays on the unix socket (`HealthHandler`), where the image HEALTHCHECK and `whalenurse healthcheck` use it. The reason is in the token-protected status.
3. **`/metrics` off by default; on, behind the token.** Unchanged.
4. **DNS rebinding fixed.** Without a token: Host `localhost`, `127.0.0.1`, `[::1]` and `WHALENURSE_HTTP_ALLOWED_HOSTS`, else 403. Choices made: the port is ignored; names compare lowercase with a trailing dot stripped; list entries may carry a port or brackets (dropped); `/healthz` is exempt; with a token the Host is not checked (a proxy forwards its own name) and the variable is ignored with a startup warning; a request with no Host header (HTTP/1.0) is served. It defends against browsers only: `curl -H 'Host: localhost'` still works, which is why a network-reachable listener still wants a token.
5. **Wrong-token limit.** 10 per minute per client IP, then 429 with `Retry-After`, with a doubling block (1, 2, 4 ... 15 minutes, strikes forgotten after an hour). Choices made: the client is the peer address (IPv6 reduced to its /64, which a client controls entirely); **`X-Forwarded-For` is ignored** (forgeable, and honouring it would let an attacker rotate addresses), so behind a reverse proxy all users share the proxy's budget and one guesser can lock everybody out; a request with no credentials is not a guess (a browser sends one before its prompt); a right token does not reset the count; **while blocked the right token also gets 429** (otherwise the block only slows guessing); `/healthz` is exempt; the block is logged once; 4,096 tracked clients. **Open for M6: a trusted-proxy option** (honour `X-Forwarded-For` from a listed proxy address) so that the budget is per real client.
6. **Skipped rungs have their own marker.** From the open incident's `RungUnavailable` events (one read of the log per page, matched on the `incident` attribute), exposed as `healer.skipped_rungs`. The detail page says "recreate skipped – not available" and lists the reason; the list says "1 of 3 rungs run, 1 skipped (not available)". If the events were pruned by retention the marker disappears and the rung looks run again (retention is 30 days by default, longer than any open incident).

## Screenshot review fixes (the maintainer's list, 19 Oct 2026; plan v3.9 item 17)

The first screenshots (`docs/screenshots/`, taken from a real demo stack) showed these; the maintainer asked for them to be fixed (not the host paths in the compose labels, which stay by design), and the screenshots were retaken.

1. **641 to about 790 px had a page-wide horizontal scroll** (the containers table has seven columns and needs 789 px). Cards now start at 900 px, and every table is wrapped in a `.tablewrap` that scrolls by itself. A sweep of 27 widths (320 to 1440, with 640/641 and 899/900/901) over 9 pages found no page-wide scroll and no element outside the viewport. **A bug of my own first try:** I made each `td` a two-column grid, which scatters a cell with several children (a badge and a text, a link and a key): "1 of 2 rungs run" landed in the label column and badges stretched across the card. The screenshots showed it; the label is now absolutely positioned and the content flows in the right column.
2. **A Paused row** links to `/containers?scope=<scope>` (the containers under that pause scope, same rule as the engine). A container that is gone, or a key with no page, is plain text. `TestEveryLinkOnEveryPageWorks` follows every link of every page (also after a container was removed) and fails on any non-200; it was run against the old behaviour and fails there with the 404.
3. **`EventAttributed` hidden** by default in "Latest events", the timelines and History, with a "Debug (everything)" filter and `?debug=1`. ### The last round (plan v3.9 item 18)

1. **Copy button**: it was absolutely positioned over the end of the `<pre>` and covered text on long lines. `.cmd` is now a flex row: the `<pre>` takes the room and scrolls, the button sits beside it. A check in the audit script measures that no button overlaps its code (0 on every page, all sizes).
2. **Plain SUSPENDED text** (banner, and the `Suspended` row): built from the engine's message `recreate skipped by the drift guard (<finding>): <why the incident opened>` by `suspendedText`; the finding is mapped to words (`config:` findings and `config --hash` mismatches to "the configuration or image changed since the container was created", a moved tag to "the image tag moved ...", anything else, such as "can't verify", is shown as written). The restart clause is added only where the page knows a restart ran (the banner: the ladder starts with `restart` and one rung ran). The timeline row says only that the recreate was blocked by the drift guard, because the `DriftBlocked` row next to it has the explanation; both keep the raw text under "details". A Suspended message that is not a drift block (the ladder, flapping) is not touched. The parsing splits at the last "): ", so a reason that itself contains "): " would be cut oddly; it only affects wording.
3. **Blocked rung**: `restart ✓ → recreate ✗ blocked (drift)`; the rung is the first one that did not run when the container is SUSPENDED for drift (the engine does not count a blocked rung as run, so this is the rung the guard stopped).
4. **Upgrade card**: the raw message line is gone.
5. **Paused event**: "for 2h, until 19:05" (the date is added when it is another day).
6. **Cards**: `td.none` cells (health, incident, cooldown) are hidden up to 900 px and shown in the table above it; checked in Chromium at 390, 768, 900 (0 of 12 visible) and 901, 1440 (12 of 12).

`TestADriftSuspensionReadsInPlainLanguage` runs a real drift block (the compose fake) through the daemon, the store and the pages and checks the banner, the ladder, the list and both timeline rows; `TestFriendlyTextsAndCards` and the unit tests in `internal/web` cover the rest. The history page and the other shots that show these texts were retaken too (overview, containers, detail-suspended, detail-upgraded, history, in all sizes and themes); `detail-sidecar-*` shows none of them and was left.
