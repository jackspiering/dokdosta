How whalenurse uses it: per URL, `router.NewWithOptions(nil, types.SenderOptions{Timeout: …})` and `Locate(url)`, which parses and initialises the service; then the service's own `SendContext` (or `Send`, for one without a context) is called **by whalenurse, under a recover**, with a deadline and the title as the `title` param. **Why not `router.SendContext`:** the router runs each service in a goroutine of its own with no `recover` (`pkg/router/router.go`, `sendToService` at v0.22.0, which has no `recover()` at all), so a panic in a service would crash the daemon, and a dead daemon heals nothing; the same release's notes include "stop custom url panic". A panic is now a failed delivery (counted, logged redacted). Residual risk: a panic in a goroutine that a service starts itself still cannot be caught. The generic service's plain template posts only the message, so a webhook receiver that wants the title should use `template=json` (`generic://host/path?template=json&disabletls=yes`, which the integration tests use).

## Decisions the plan leaves open

1. **What is notified.** The task's list plus three that the engine already emits and a person would want: `DriftWarned` (§3.6 says `warn` "says so"), `NeedsRecreate` (a recreate that cannot run: otherwise the user never learns that healing is not happening), and `RungsDisabled` (that is the version-gate warning). Left in the log and the store: `IncidentOpened`, `ActionStarted`, `RungUnavailable`, `WaitingForParent`, `ActionRefused`, `DependentPostCheck`, the manual-stop and restore events.
2. **Dedupe needs an incident id.** Events carried none, and rebuilding incident state inside `notify` breaks after a restart (no `IncidentOpened` arrives for an incident that is still open). So `engine.emit` adds an `incident` attribute (the opening time, RFC 3339 nano) to every event of a key with an open incident. The identity of a message is (event type, key, discriminator, incident). Events with no incident are deduplicated for 24 h (`NotifyOnly`, `NeedsRecreate`, the version-gate warning, `Unsuspended` without an incident), so a `restart: "no"` parent that stays down is not announced again by every poll, but is after a day.
3. **Dedupe is persisted** (review follow-up 1; first built in memory only, then persisted on the maintainer's decision).
4. **`DriftBlocked` and `Suspended(drift)` are one message.** The engine publishes both; the first carries the findings. A test pins exactly one.
5. **Rate limit shape.** A sliding window of one hour per URL, `WHALENURSE_NOTIFY_RATE_LIMIT` (default 20). Routine messages may use half of it, important ones all of it, so that a storm of "restarted" cannot swallow "giving up". Held-back messages are counted, shown in `status`, and the next message that goes out says how many ("N earlier messages were held back"). I did not build a separate summary message. Not in the task: the 2:1 reserve and the default of 20 are mine.
6. **Retries.** A failed delivery is retried twice (after 2 s and 10 s) before it counts as failed, because a push service that hiccups should not lose "giving up". The retries run in that URL's worker, so they delay only that URL's later messages. Shutdown gives the queue 5 s, then aborts what is in flight.
7. **Message shape.** Title `host: container headline`, body: the key line, then cause and next step (`whalenurse unsuspend project/service`). 72 and 360 runes. The long container name is what is cut, never the headline. A body of 300 runes was too tight for the drift guard's real text (the compose-upgrade note alone is 150), so the template shortens the guard's wording (compose's own dry-run text, the upgrade parenthetical) and says the upgrade in the hint, with the versions.
8. **The compose-upgrade hint** is text in the drift message ("compose upgraded 5.2.0 to 5.6.0 since creation: maybe a new hash layout, not an edit. If the file is fine: docker compose up -d web"), matched on the guard's own wording (`compose upgraded from X to Y`, `can't verify drift (compose`, `the tag moved`, `would recreate`, `config --hash is`). If someone rewords the guard's text the hint silently disappears; the templates test uses the real wording, and the integration tests do not cover it.
9. **The redactor.** Built from the configured URLs: the URL, what follows the scheme (Shoutrrr rewrites `generic://` to `http(s)://` in client errors), the user info, host, path segments of 6 runes or more, the whole path, query values of 4 runes or more (and comma-separated pieces of them), each also URL-escaped. 4 and 6 are a compromise: a path of `hook` is not masked, because it would turn "generic webhook" into "generic web***", at the price that a real secret that short in a path is not masked either (tokens are longer). Verified by mutation: with the redactor disabled the token test, the redaction tests and the ping test fail.
10. **Invalid URLs do not stop whalenurse.** A URL Shoutrrr rejects is logged at error (position and scheme, redacted reason), listed as `INVALID` in `status`, and skipped. `notify test` reports it as FAILED. Healing carrying on matters more than a typo in a notification URL; the cost is that a typo is only seen if someone looks at the log or runs `notify test`.
11. **`notify test` runs in the CLI process** from the environment, not through the control socket: it needs no daemon, so it works before the first start (`docker run --env-file … whalenurse notify test`) and under `docker exec` (the container's env). It sends one attempt per URL, sequentially, in `[dry-run]` marking when `WHALENURSE_DRY_RUN=true` is in that environment (note: `run --dry-run` as a flag is not visible to a separate `notify test` process).
12. **The uptime ping** is a plain GET, not Shoutrrr, with the same timeout and redactor. It pings at once and then every `WHALENURSE_HEARTBEAT_INTERVAL`, only while `Healthy()` is true. It is called the uptime ping in code, because "heartbeat" already means `last_seen`. It also pings in a dry run.
13. **`WHALENURSE_NOTIFY_URLS` splitting.** Whitespace, a newline, or a comma followed by `scheme://`; a comma elsewhere belongs to the URL (ntfy `tags=a,b`, Telegram `chats=a,b`). A URL with a space in it cannot be given (percent-encode it).
14. **Panic isolation.** The router's send is not used (see the upstream table's last paragraph); `Locate` and the send are under a recover, the worker's call to any `Sender` is too, and so is the dispatcher's handling of each event (a template bug drops that event and counts it).
15. **New variables** (plan §4): `WHALENURSE_NOTIFY_TIMEOUT` (10s), `WHALENURSE_NOTIFY_RATE_LIMIT` (20), `WHALENURSE_HEARTBEAT_INTERVAL` (5m). The "accepted with a warning, ignored until M3" entries for `NOTIFY_URLS` and `HEARTBEAT_URL` are gone.

## Review follow-ups (v3.7 approved 19 Oct 2026)

The maintainer's answers to the open questions, implemented in a follow-up commit on PR #11:

1. **The dedupe is persisted.** `internal/store` schema 2 adds `notified (id PRIMARY KEY, type, key, at)` with an index on (type, key); a schema-1 database is migrated in place (tested). The notifier takes a `notify.Ledger` (the store implements it): it loads the rows younger than 24 h when it starts and writes a row when it accepts a message, in the dispatcher goroutine, never the engine's. Rows are pruned hourly with the history. `run --dry-run` has no store, so its ledger is memory only. An unreadable ledger is logged and the dedupe starts empty. A message is recorded as accepted when it passes the dedupe, not when delivery succeeds: a delivery that fails after its retries is not sent again after a restart. Tests: the real store across two notifier lifetimes (a repeated `NotifyOnly` and `Suspended` are silent, a new incident and another container are not), the ledger round trip, expiry, forget and the migration.
2. **`RateLimited` is notified**, important, **at most once an hour per URL** whichever container hit it ("action rate limit reached, healing waits"; the message says every container waits). The spacing is per URL and in memory (after a restart the next one may come sooner, which is also when the persisted rate-limit ledger of the engine can run out again). A skipped message is counted (`throttled` in `status`) and spends none of the URL's 20 an hour. The key line names the container that hit the limit first.
3. **20 an hour per URL stays the default.**
4. **`Unsuspended` is notified, as a routine message** ("unsuspended", the reason: back to healthy, a `create`, a start after a manual stop, or the command). Two consequences I had to decide: (a) within one incident the container can be suspended, come back, and fail again before `RECOVERY_PERIOD`, so `Suspended` and `Unsuspended` are made news again by each other (the ledger rows of the other type for that key are forgotten), otherwise the second "giving up" would be swallowed and the last word the user heard would be "unsuspended"; (b) an `unsuspend` by command is never deduplicated. Recovered still arrives `RECOVERY_PERIOD` after it.

Also: the plan's status line, CLAUDE.md and `running.md` are updated, and plan §3.10 now says the `notified` table is built.

## Tests

- Unit (no Docker, no process; `go test -race ./...`): templates for every notified event (host and key present, limits under worst-case text, dry-run marker in title and body, drift hints), events outside the list are not sent, a drift suspension is one message; dedupe per incident, per key, 24 h without an incident, never for pause and resume, once per process for the version-gate warning; the rate limit with the critical reserve, per URL, and the "held back" note; retries, counting and redacted logging; `Handle` with a hung URL, a full queue and a stalled dispatcher; one URL never delaying another; the per-attempt timeout; shutdown flush and abort; invalid targets; redaction over six URL shapes and five kinds of error text; URL splitting (with `tags=warning,skull`); the uptime ping; **the whole ladder through the real daemon** (restart, recreate, one giving-up with the cause; a recovery; a dry run marked and doing nothing; a hung URL not delaying healing); **Shoutrrr's generic service against a real HTTP receiver** (JSON title and message, 401, 500, connection refused); and **the token grep** (`cmd/whalenurse`): tokens in the user info, path and query of URLs that fail by 401, 500, connection refused, an unknown service and a non-URL, plus the ping URL; the logs, `status` (text and JSON), `/healthz`, the socket status and the `notify test` output must hold none of them nor any whole URL. Mutation-checked: disabling the redactor fails the token test, the redaction tests and the ping test; making `Handle` block, or dropping the worker's recover, fails theirs. A panicking sender is a failed delivery and the other URL still gets its message.
- Integration (CI only, behind the guard, `whalenurse-test-*` only, loopback receiver): the ladder ending in SUSPENDED (restart, recreate, exactly one giving-up with the cause and the unsuspend command, a dead URL beside the working one, no more messages afterwards, no URL in the status), a recovery (restart, recreate, recovered, no SUSPENDED), a dry run (every message marked, container untouched). The existing `TestImage` and the rest are unchanged.

## Not verified

- **The integration tests were not run locally** (the plan forbids it; CI is their only run).
- **A real push service.** Only the generic service was exercised (a loopback webhook). ntfy, Gotify, Discord and Telegram were not sent to: that needs real accounts. `notify test` is the check for the maintainer's own URLs ([maintainer]).
- **TLS from the image.** The loopback tests use plain HTTP. HTTPS needs the CA bundle in `gcr.io/distroless/static`, which ships one, but no test here makes an HTTPS request from the built image.
- **A panic in a goroutine a Shoutrrr service starts itself** (the sender-level recover cannot see it). No such service is known; the services of v0.22.0 were not audited.
- **A restart of the real binary mid-incident** with notifications on: the persisted dedupe is tested with a real store across two notifier lifetimes in unit tests, but no integration test restarts whalenurse and checks the receiver.
- **The `incident` attribute** is covered by engine tests, and all existing tests pass unchanged, but no test restarts whalenurse mid-incident and checks that the notifier says nothing twice.
